Policies (filter + authorize before each LLM request)
Policy.ToolFilter %AI.Policy.Discovery
extends %AI.Policy.Discovery
%Resolve() runs before each LLM request. Strips framework auto-discovered waste (%AI.Tools.FileSystem, SQL, ShellTools, %AI.Agent.Skill) and deduplicates entries by class name. Keeps first occurrence per class.
Saves ~2,100 tokens from framework waste + ~6,900 tokens from deduplication = ~9,000 tokens per request eliminated.
Policy.ConfirmationGate %AI.Policy.Authorization
extends %AI.Policy.Authorization
Per-tool confirmation prompts. MUTATINGPREFIXES list (Create, Delete, Start, Stop, Send, etc.). Pre-approved tokens (set by ChatService when the user approves) bypass the gate.

Manager.Build() — Request-Time Agent Assembly

Every chat request builds a fresh agent instance. This 6-step pipeline wires all components.

1
%New(provider) + %Init()
Instantiates the HealthInterop agent class with the configured Bedrock provider. %Init() auto-discovers every non-abstract %AI.Tool subclass in the namespace and adds them to the FindTools catalog. This includes our 5 Tool classes, but ALSO framework waste (%AI.Tools.FileSystem, SQL, ShellTools) and the abstract Skill.Base.
2
SetDiscoveryPolicy(ToolFilter) NEW
Registers the ToolFilter DiscoveryPolicy on the ToolManager. %Resolve() runs before EACH LLM request: strips 5 framework waste entries, deduplicates by class name. The LLM sees 14 clean entries instead of 19+ duplicated ones. Saves ~9,000 tokens per request.
3
Overlay: system prompt, temperature, MaxIterations
Reads user customizations from Data.AgentOverride via Editor.Overlay. Applies system prompt override, temperature override, MaxIterations override. Falls through to compiled class defaults if no override exists.
4
UseToolSet(Tool.*) — direct registration CHANGED
Calls agent.UseToolSet() directly on each Tool class (Production, Transform, Testing, Catalog, Monitoring). This makes individual ClassMethods callable via ExecuteTool. Previously: MCP.RegisterToAgent called UseToolSet on ToolSet wrapper classes that <Include>d the same Tool methods — doubling every definition. Now: one UseToolSet per Tool class, no wrappers needed.
5
SkillLoader — register 9 sub-agent skills
Reads SKILLS parameter (overlay-aware). For each skill class, constructs an %AI.Agent.Skill via the Skill.Base workaround (fixes $ZF marshal bug) and adds it to the ToolManager. Skills are invoked as sub-agent tools by the LLM.
6
ConfirmationGate + Catalog.Attach
Sets the ConfirmationGate authorization policy (mutating tools require approval). Then attaches search_ens and search_hs KnowledgeBase tools if their vector tables have rows. These RAG tools are added OUTSIDE the ToolFilter because they're registered after %Init().
